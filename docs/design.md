# 0.2.0 原生界面调整

采用 Emil Design Engineering 的层级、按压反馈和可访问性原则，通过 SwiftUI 原生控件实现，不引入 WebView。

| Before | After | Why |
| --- | --- | --- |
| 大幅宣传文字和 PREVIEW 英文占位 | 原生大标题、校园卡余额和宿舍优先 | 首页先呈现实际使用数据 |
| 只有热水操作 | 余额卡片与热水操作独立分组 | 查询和控制状态清晰，各自失败互不影响 |
| 配置按钮散落底部 | 右上角设置，分校园卡与热水两组 | 常用操作留在首页，敏感配置不回显 |
| 浅色暖白固定背景为主 | 系统 grouped / secondaryGrouped 配色 | 自动适配手机深浅色与系统对比度 |
| 余额字号尚未定义 | Dynamic Type 缩放、等宽数字、48pt 基准 | 保持余额优先级，适配长金额和大字号 |
| 默认按钮样式 | 52pt 操作区域，120ms 轻微按压，尊重减少动态效果 | 即时触摸反馈，避免装饰动效 |
| 校园读取失败可能显示空值 | 上次有效余额、查询时间和固定错误状态 | 不把失败解释成零余额或刚更新 |

不为每次刷新播放入场或数字跳动动画。不改变热水交易状态机与快捷指令语义。

## 0.4.1 预约与付款状态优化

| Before | After | Why |
| --- | --- | --- |
| 预约后仍显示程序选择，可能误以为能改已有订单 | 未决订单只显示订单与付款操作；结束后恢复程序列表 | 对应先预约、再付款的真实流程 |
| 无订单号时刷新按钮被禁用 | 允许只读核对本人的活动订单，匹配字段后恢复 | 回执异常不应阻断查询恢复 |
| 未付款取消单仍占大块页面 | 保留为紧凑历史条，显示已取消和未支付 | 保留证据且不妨碍下一次选择 |
| 错误信息位于程序列表之后 | 在订单卡内展示订单错误 | 让反馈靠近触发动作 |
| 设备状态可能仍显示预约前空闲 | 未决订单优先显示已预约/核对中/付款待确认 | 避免与订单卡冲突 |

预约倒计时只用于提示，到期再只读查询服务器；本机计时归零不直接把订单标为取消。

## 0.4.5 下单与支付宝跳转提速

| Before | After | Why |
| --- | --- | --- |
| 核对订单后确认下单，再点去支付并再次确认 | 核对页统一显示金额、扣费及设备运行提示，主按钮改为“下单并前往支付宝” | 同一次明确确认授权预约及付款请求，减少两次点击 |
| 获取付款参数前才串行查询渠道 | 保存新订单号后，在核对订单详情的同时预查询渠道；已有未付订单刷新时也可准备 | 重叠独立的只读请求，减少付款按钮后的等待 |
| 支付准备与真实支付边界不清 | 仅缓存45秒的渠道元数据，真实财务参数仍在确认后请求一次 | 避免提前扣款、链接失效或重复交易 |
| 回执异常恢复订单后可能继续后续步骤 | 创建结果不明确时停在订单卡，保留独立付款确认与取消订单 | 不将恢复成功误当作本次连续付款已确认 |

保持原半屏核对布局和取消入口，不增加装饰性动效。实际支付宝内部授权/收银台加载耗时不由本 App 控制；本轮无真实交易测速。

## 0.4.7 热水扫描与状态审查

| Before | After | Why |
| --- | --- | --- |
| 扫描6秒，同名目标数量不为1时统一报错 | 扫描12秒，分别显示未发现和多个同名设备 | 区分现场未广播与同名歧义 |
| 新一轮启动忽略上次保存的外设标识 | 同一机器优先选择上次设备；未发现时仅允许唯一候选，并照常读取机器编号核对 | 改善宿舍同型号设备的识别，不随机挑选设备 |
| 热水出错时标题仍为“本次已结算” | 出错显示“本次未完成”，旧结算显示“上次已结算” | 避免把历史结果误读为本次成功 |
| 缺少只读蓝牙检查 | 增加折叠的连接检查，仅扫描、不连接写入或请求授权 | 可以排查现场广播而不产生用水交易 |
| 服务器已确认洗衣中仍提示付款结果未知 | 对已付款/运行状态隐藏旧的未知提示 | 与真实订单状态保持一致 |

## 0.7.0 U净本人短信登录

| Before | After | Why |
| --- | --- | --- |
| U净首次登录显示适配中，需开发者导入会话 | 增加本人手机号、验证码与明确协议选择 | 对齐最新官方正常登录抓包，不使用关闭验证参数 |
| 机器库按 token 摘要隔离 | 正常登录后使用服务器返回的 app 账号 id 分区，续期保留常用机器 | id 与 userId 在官方响应中不同，不能混用；更换账号不沿用他人缓存或订单 |
| 账号和当前机器混为一个配置 | 钥匙串单条连接记录保存本人账号与可选常用机器 | 新用户可先登录，再扫码；不需要预先填写机器编号 |

验证码请求仅含 mobile、type=1；登录仅提交 mobile、captcha。验证码与手机号不写入本地账号记录；token 保存在钥匙串，SMS 请求前保留60秒冷却，超时不自动重发，服务器要求额外验证时停止正常登录流程。应用使用自己的安装UUID和客户端标识，不复制抓包中的Cookie、设备标识或位置。隐私与服务协议链接从官方安装包取得，并确认官方HTTPS页面可访问。


2026-10-29 首次热水配置改为安装包提供通用参数，学校登录后直接核验本人身份；本地 build 33 / alpha16 候选随后由 Beta 2（iOS build 36 / Android alpha22）取代。当前安装、功能与验收范围见 [Beta 2 说明](release-0.8.0-beta.2.md)。

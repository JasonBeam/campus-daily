# 洗衣已完成却没有提醒：build48 候选

2026-11-03，用户报告真实订单已显示洗衣完成，但没有收到通知。当前手机 build47，洗衣结束提醒开关为开启。读取本机偏好时没有本单提醒跟踪键或到期时间；当前订单为状态 50（已完成），remainTime 仍有数值。没有证据证明本次曾成功安排倒计时通知。

代码中的确定缺口：iOS 策略对状态 50 无条件返回 ignore。如果 App 没有在运行期间安排倒计时，而在订单已完成后才刷新，就不会安排任何通知。测试通知独立于订单通知，收到十秒测试不能证明真实订单链路可用。此前“完成不能撤销预测”的修正把所有完成情况都忽略，漏掉了完成时补发这条路径。

## 修正

- 保留按最新运行订单剩余时间安排倒计时的流程。
- 本地创建时间在最近 24 小时内、身份和机器匹配、且由服务器新近查询确认完成的订单，即使从未保存过倒计时，也安排一次“洗衣完成”通知。
- 历史订单、失败、取消与未启动订单不当作完成；同单成功安排的完成通知保留哈希去重标记。运行中通知已实际出现在系统通知列表时，也记录该单已提醒，避免反复提示。
- 不再把“倒计时已过且不在待投递列表”推断为用户收到过通知；投递成功与否不能只靠时钟猜测。
- 完成提醒成功交给系统后，才撤掉同单尚未投递的预测，避免完成通知安排失败时连原预测也丢失。不删除已经投递的通知。
- 前台通知同时请求横幅、声音和通知中心展示。
- 设置显示实际状态：尚未安排、预计提醒时间、已安排完成通知或通知权限问题。
- Android 同步“没有倒计时也能在完成刷新时补发一次”的路径，并在完成通知成功提交后取消旧预测。

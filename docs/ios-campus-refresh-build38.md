# iOS 校园余额下拉刷新修复候选 build 38

日期：2026-10-29。包含 build 37 热水诊断与连接修订，本轮新增校园卡、电费刷新修复。仅本地测试候选。

## 用户反馈

同一已登录账户：首页下拉提示“暂时无法连接学校”，在设置中刷新却可恢复。聊天截图中还出现过热水“结算完成”，仅证明截图当时页面状态，不能确认此前短暂出水问题的成因或修复。

## 代码发现

- 首页下拉和设置按钮都调用 `CampusModel.refresh(force:true)`；设置入口启动独立 Task，而下拉入口继承页面刷新任务的生命周期。
- 学校 URLSession 的 `cancelled` 错误被统一转换成 network；校园卡的登录桥接还会吞掉该取消，继续后续请求。
- 刷新尝试开始时即更新时间，失败同样占用 300 秒自动查询间隔；手动强制刷新虽可绕过，但会造成失败后自动查询迟迟不恢复的感觉。

代码与模拟请求证实上述取消处理缺陷。测试者没有提供该次失败的网络错误码，因此不能断定他每次失败都由取消造成，也不能把问题归因于 Cookie 时长。

## 修改

- 单一只读刷新任务独立于下拉手势生命周期。多个入口同时刷新时等待同一项工作，避免请求重复或相互打断。
- URLSession cancelled 和 Swift 取消继续作为取消传播，不生成“学校无法连接”或“登录过期”，不走捕获卡号的后续查询。
- 取消时保留旧的校园卡、电表余额和查询时间，不把缺失余额当作 0。
- 自动查询间隔只从成功完成的余额读取计算；失败或取消后允许重新尝试。学校真正返回过期仍要求本人重新登录，不伪造续期。
- 账号或电表绑定在读取中变化时忽略旧归属结果，并在当前读取结束后检查新归属。

# 已停水会话恢复候选（build43）

**现场新证据后撤回：** 用户补充自己洗完约十分钟后已有他人使用同一水控。恢复操作时水控已从保存的 20 字节回复变为 A5；候选被数据变化守卫阻止，未调用服务器结算。随后普通结束收到 A5，进入 closeWritePending。无法将共享水控的当前消费数据证明归属于原会话，build44 已默认禁用生产 Provider 的此恢复能力，UI 不再显示补交入口。不得把下述离线成功模拟当作可对真实共享设备补交的依据。

目标是处理本人按机身按键停水后，AA 查询返回本机完整 20 字节帧、原 finish 因非 A5 而退出的未结算会话。

## 实现及边界

新增显式 settleStopped。只对 active、已标记待核对、有本次授权且保存了已验证设备回复的会话开放。再次连接保存的同一外围设备，只发送 AA；当前数据必须逐字节等于保存的回复，否则停止。匹配后先持久化消费数据和 settlementPending，再单次调用既有 analysisOfBathingConsumptionData 结算接口；仅服务端成功确认后记录收据、结束时间及 settled。网络未确认或重启不自动重复请求。

不会发授权、AC 关水或另一套协议的开阀请求。不会由前台自动检查触发。热水页提供标注“待验证”的恢复入口及提交确认，说明可能扣除本次费用；真实提交由用户决定。

这是针对本次卡住状态的恢复候选，不是已完成的机身自动结算功能。已有官方代码证明完整状态/消费帧及消费处理接口的存在，但没有直接抓到机身按键后的这条恢复路径获得服务器成功响应，不能宣称接口已接受该用法。现场服务器验收仍是必需证据，不得凭本地模拟收据宣称已扣费。

## 已验证

- 控制器 32 项回归测试通过，覆盖单次提交、拒绝变化的数据、写盘失败先阻断、网络超时保留 settlementPending 并防止重启重复请求。
- 使用本人导出的真实启动帧、授权应答和停水后稳定帧，运行离线重放测试通过；传输及服务端均为 mock，实际 HTTP 和蓝牙操作为零。
- iOS Release/iphoneos build43 编译成功、代码签名及 Widget 共享钥匙串检查通过。
- 给本人 iPhone 16 Pro Max 覆盖安装，前后未决会话文件哈希相同。朋友 iPhone 未变更。

## 待确认

需要用户在现场核对本人本次用水已停，并自行决定是否点击恢复提交。必须观察真实响应、费用及是否恢复开始页；不得由工具点击财务确认按钮。若响应拒绝或网络结果未确认，保留记录，不重复试扣、不用清缓存解除阻止。

本候选未公开推送、打标签或发布。Android 尚未同步。

# 学校充值微信跳转链接研究

2026-11-02。按用户要求只研究跳转，保留充值按钮，不接入新商户、不下单、不改 App 路由。

## 已找到的路线

微信官方文档确认存在三类不同入口：

| 路线 | 可以解决什么 | 本项目当前证据 |
| --- | --- | --- |
| 明文 URL Scheme | 外部链接打开指定小程序页面 | 官方能力存在；学校页面是否开放未验证 |
| 加密 URL Scheme / URL Link | 使用小程序主体签发的链接打开页面 | 没有找到学校已公开的可用链接，不能由本项目替其他小程序生成 |
| 学校官方小程序码 | 微信扫一扫/识别进入学校小程序 | 已从学校官网取得官方图片；尚未在手机识别验收 |

明文 Scheme 的形式为 `weixin://dl/business/?appid=APPID&path=PATH&env_version=release`。这是格式模板，不是本项目已经验证的链接。

官方文档明确说明：小程序主体在管理后台声明明文 Scheme 拉起能力后，开发者可以按格式拼接，无需调用生成接口。此前“所有跳转都需要 AppSecret”这种概括不准确；加密链接的生成和明文 Scheme 应分开讨论。

必要条件包括准确 AppID、已发布的真实页面路径，以及学校后台对明文 Scheme 的配置。不能把普通网页路由 `/recharge` 或 `/cashier` 当作小程序 path，也不能把网页登录参数拼入外部链接。

## 项目源码中的入口线索

学校公开网页使用 `wx-open-launch-weapp` 开放标签，目标 username 与 path 来自学校大厅条目数据，而不是固定写在通用前端脚本中。它证明学校网页有微信内打开小程序的实现，但不证明普通 App WebView 可以使用相同开放标签。

此前的热水小程序源码还包含另一个小程序标识，并要求从“工商智慧校园”调用进入。因此不能把它当作办事大厅的 AppID，更不能仅按它拼一个链接就认定能够进入充值。项目现有学校登录请求中的 AppID 参数，也尚未独立核验为办事大厅本身的 AppID。

未发现可直接使用的学校 `wxaurl.cn`、`w.url.cn` 或 `weixin://dl/business/?t=...` 正式入口。

## 下一步如何验证

优先取得办事大厅本身的正式分享链接、准确 AppID 与已发布首页路径，先验证打开学校首页。若学校已开放明文 Scheme，可测试该路线；若未开放，需要学校签发的 URL Link/Scheme，或以官方小程序码作为兜底入口。

测试必须分别记录：是否打开微信、是否打开正确学校小程序、是否进入指定页面。调用系统 open 返回成功只表示交给了微信，不能当作后两项成功。

学校首页能打开，也不等于可把“外部 App → 小程序收银台”作为充值支付链路。支付入口的后续设计仍需要核对微信支付产品规则与学校实际支持方式。本轮不为跳转研究创建充值订单。

目前可执行的结论：存在官方跳转技术路线，尚未取得并验证学校可用的一键直达链接；不能直接宣布已经能跳转充值，也没有因此删掉现有入口。

### 明文 Scheme 对照测试

为了避免猜测路径，读取本机 Mac 微信已缓存的同 AppID 小程序包，仅解析静态 app-config.json 的路由列表（不读取登录存储或账号数据）。配置显示 entryPagePath 为 pages/applet/index.html，已发布 pages 列表包含 pages/applet/index。

以此构造的对照链接：

`weixin://dl/business/?appid=wx8af2c19af1db7dbb&path=pages/applet/index&env_version=release`

实机在系统确认打开微信后，微信显示“对不起，当前页面无法访问”。因此不采用该链接。可能涉及学校明文 Scheme 配置或其他平台限制；本次仅证明这个具体链接没有成功，不把原因认定为已查明。

## 本机近7天记录

用户明确选择“仅校日常 App 内产生并保存的记录”，因此未接入学校或 U净全量历史接口，没有发起新的账单查询。

两端订单页新增“近7天本机记录”。展示最近连续7×24小时（含边界、排除未来）的热水及洗衣摘要，按开始时间倒序。历史页只读，不提供开水、关水、启动洗衣、付款或取消按钮，不发蓝牙或网络请求；状态是本机最后保存的结果。

每次保存当前会话/订单时，将无凭据的摘要写入独立本机历史区；同一记录后续更新替换原摘要，不因取得订单号、状态刷新或重启而增加副本。新订单不覆盖旧摘要。热水只在服务器已确认结算后展示返回金额；洗衣仅使用服务器订单金额，不把报价当实付，也不将已付款金额当成退款后的净消费。未确认金额明确标注。没有余额差额推算或消费总额。

新热水会话写入学校/学生身份的哈希归属；洗衣使用已有登录身份。换账号不展示他人记录，iOS 同账号切换机器不影响所属历史。原始蓝牙数据、支付链接、Token 和密码不进入摘要。iOS 使用受保护且不备份的独立目录；Android 使用原有 SecureStore 加密存储。

已有可归属的洗衣记录和带归属的水控存档可补入；旧版缺少账号归属的热水记录不猜测归属，已被旧版本覆盖且未保存的记录无法补回。旧待核对快照不会覆盖已经保存的较新结算摘要。原始未决记录仍保留。历史保存失败提示列表可能不完整，不阻断或重发设备/扣费操作。

## 学校入口研究

截图仅证明之前那条“添加到桌面”入口在另一访问者处被拒绝，尚不能区分绑定微信身份、设备或其他桌面链接限制。不能概括为所有 Scheme/URL Link 都只能单人用。此前保存的微信官方 URL Link 接口说明明确写有自2023-12-19取消一人一链限制；链接产品类型、签发配置与该桌面入口必须分开。

本次再次尝试读取微信在线文档：网页工具未取得正文，直接读取也未取得可解析正文，因此不声称完成了当前官方条款的全量复核。已有官方文档副本、学校资料和此前真机记录支持以下条件比较：

| 方式 | 当前结论 |
| --- | --- |
| 复用桌面链接 | 已在另一访问者失败，已移除 |
| 学校正式签发的多人 URL Link | 可作为候选，需要学校维护方提供并核对有效期；不能替学校私自签发 |
| 明文 Scheme | 需要学校后台开放和真实页面路径；此前已用正确 AppID/pages/applet/index 测试失败，不能直接重新宣称可用 |
| 微信 OpenSDK 拉起学校首页 | 需要校日常自己的微信移动应用注册、审核及相应权限，并确认目标小程序条件；项目尚未具备已验证配置，不能用学校的小程序AppID冒充校日常移动AppID |
| 学校官网小程序码 + 微信收藏/最近使用 | 当前无需复用桌面链接的替代入口；已加入两端，识别仍待不同用户真机验收 |

两端加入学校官网提供的原始小程序码、官网说明和搜索名称。iOS 可打开系统图片分享/保存面板；Android 提示截图后从微信扫一扫相册识别。首次进入后可添加到微信“我的小程序”。本次重新下载官网图片核对 SHA256，与打包图片相同。没有更改或生成小程序码，没有代用户分享给任何人。

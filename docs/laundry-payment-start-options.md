# 付款后启动洗衣：方案比较

结论：现有支付入口下，最容易先落地的是“短时后台核对＋回到前台兜底”；如果目标是付款后完全不用回 App，授权服务端查本单并启动更适合。原生支付宝支付或官方 H5 转 Native 能改善回跳体验，值得单独验证，但当前支付样本不足以证明兼容。

## 已核对的现状

- 本人已使用的支付响应是支付宝内的 U净网页入口，启动记录为 checkout_opened；本次离线检查没有发现该笔支付可直接交给原生 App 支付 SDK 的签名订单串。
- 校日常已有原生支付 SDK 分支和 URL 回调处理，但实际网页入口仅通过 UIApplication.open 打开；“打开成功”不等于收到支付结果。
- 现有支付策略已经优先选择官方返回的 alipay 渠道，再选 alipayF2F。本次没有创建订单或请求新的付款参数，不能断言当前账号永远没有原生支付渠道。
- U净前端中，支付宝网页支付使用 ap.tradePay，成功后回到其自己的 paystatus 页面；洗衣启动使用另外的 control/start 流程。未找到足以确认“任意订单付款即自动启动”的通用开关。
- 当前立刻洗衣通过 U净订单的新状态确认付款、待启动状态、设备和程序，再提交一次启动。付款回跳和客户端支付结果都不能代替这一核对。
- build51 后已合并启动前重复读取，并在回到前台时立即查询、短时快速查单。本次没有新的真实时延测量，不能承诺固定几秒启动。

## 对比

| 方案 | 付款后要做什么 | 不回 App 是否能启动 | 当前证据与适用性 |
| --- | --- | --- | --- |
| 现有前台启动 | 返回校日常，保持前台 | 不保证 | 已由用户验证启动成功；操作明确，不依赖后台时间 |
| 短时后台核对＋前台兜底 | 付款较快且系统仍给后台时间时无需返回；未启动则回 App | 部分场景可以 | 可用 iOS 官方有限后台任务实现；尚未开发和实机验证，系统可提前结束 |
| 原生支付宝 SDK／官方 H5 转 Native 回跳 | 完成支付后由支付流程返回校日常；部分收银台仍可能需要点“完成” | 通过回跳恢复 App，再查单启动 | SDK 能力存在，工程已有原生分支；当前 OAuth/支付宝容器链接不是可直接送给 H5 转 Native 的网站支付请求 URL，兼容性未验证 |
| 授权服务端查单并启动 | 支付完成后无需切 App | 可以设计为不依赖手机前台 | 需新增常在线任务执行器及 U净授权，可考虑本人 NAS；仍取决于 U净订单更新、网络和设备状态，不承诺秒级或全场景成功 |
| U净官方付款后启动 | 仅付款 | 若官方提供该能力则可以 | 当前观察流程付款与启动分离；尚未找到支持证据，需要官方渠道确认 |

## 推荐顺序

1. 近期先做短时后台核对候选，保留已经验证的前台路径。只跟踪明确选择“立刻洗衣”的本单，在拉起支付前申请后台时间；系统到期停止工作，回 App 后继续核对。不能用音频、定位或循环申请后台时间来伪装保活。
2. 同时在下一次本人正常洗衣时，核对官方支付渠道及实际支付 URL。原生 App 支付签名串可以沿现有 SDK 分支验证；只有实际网站支付请求 URL 才适合验证官方 H5 转 Native，不能修改或拼造已签名的支付参数、商户身份和回跳字段。
3. 若要求“不管支付多久、是否返回 App，都应自动启动”，再设计授权服务端执行。客户端和服务端必须共享本单的唯一启动执行权；不能让两边各自独立查询后同时发送。任务需持久化、限时、匹配用户/设备/程序；结果不确定时继续查单，禁止重发控制。U净登录会话将用于服务端代办，这需要单独确定托管位置和授权方式。

## 官方依据

- Apple：后台任务只获得有限执行时间，可能无法获得时间；必须在到期时结束。BGAppRefreshTask 和后台推送的执行时机由系统决定，不适合承诺“付款后立刻唤醒”。
  https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time
  https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app
- 支付宝官方文档：手机网站支付转 App 支付的 payInterceptorWithUrl 使用实际网站支付请求 URL，支持传入应用 scheme 和结果回调。本地已使用的 AlipaySDK 15.8.30 头文件也包含该接口；它的存在不能证明 U净当前支付宝内网页入口可转换。
  https://developer.alibaba.com/docs/doc.htm?articleId=105695&docType=1&treeId=193

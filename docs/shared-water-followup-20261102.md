# 共享水控：现场后续及处理

## 新证据

用户明确说明本次洗完约十分钟后，已有其他人使用同一台水控。19:13 左右，恢复候选读取到 A5，与保存的停水回复不同，触发 stateChanged，未提交结算。随后普通结束先收到 A5，AC 后又收到 A5，没有消费帧；保留 closeWritePending。未发现消费数据、收据或服务器结算请求。

因此现在读取的物理设备状态不能直接用于原用户这笔消费。不能强制清记录、重新授权、重发 AC 或用后续用户的数据试扣费。

## build44

- 恢复接口要求显式 Provider 能力；默认关闭，生产 HTTPSWaterProvider 不支持。Mock 仅用于测试候选状态机。
- closeWritePending 可只读 review，但不重发结束指令；结算结果未知的 settlementPending 仍不得用设备空闲状态解锁。
- AC 返回 A5 显示水控忙/结束未确认，不再误报帧格式错误。
- 页面主按钮改为“核对结束结果”，不再显示无法使用的“开始洗澡”。补交入口不可见。
- 35 项控制器测试通过，含共享设备恢复默认禁用和忙碌结束后的只读恢复；编译签名通过，已给本人手机覆盖安装。

## 账单只读调查

旧 lxt6 消费列表接口 HTTP 200/code 0，但返回空列表，未取得对应结算证据。

学校官方 GDWater 网页代码另提供 getWaterMoney 和 wxschoolsign/errOrder（代扣失败列表），以及独立的 repeatDk 操作。只允许查询前两者；不调用 repeatDk、签约或付款。旧 HAR 登录查询返回登录过期，不能把它当作当前 App 已登录状态失效。

build45 仅增加显式 --check-water-billing 私有诊断：使用当前 App 已保存校园登录查询这两条只读接口，结果写入受保护的本地 Documents/water-billing-read-only-private.json。不会导出登录凭据、连接蓝牙或触发扣费。其结果仍需按实际返回验证，不能提前宣称已查询到本单。

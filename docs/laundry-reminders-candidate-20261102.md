# 洗衣结束提醒本地候选版

2026-11-02，继首轮研究后，用户选择暂不创建真实订单，先开发提醒。

## 行为

- iOS、Android 洗衣页新增默认关闭的“洗衣结束提醒”开关。由用户打开时申请系统通知权限；拒绝不影响原有洗衣功能。
- 付款后返回校日常，查询确认订单已进入运行状态且有有效剩余时间后，安排一条本地“预计洗衣结束”通知。按服务器观察时刻计算截止时间，不从每次打开页面重新倒计时。
- 账号范围与订单组成不可逆散列键，不在通知中写入个人身份、token、订单号或机器地点。同单更新覆盖计划，避免重复提醒。
- 前台每 30 秒读取当前订单，不在后台无限轮询。确认状态 50 后处理“洗衣完成”；已提醒过预计结束的同一单不再重复响铃。51/52/53 撤销预测，不会当成洗衣完成。
- 启用时不为历史已完成订单补发通知。未知状态、缺失剩余时间、过期结果和网络失败不伪造完成。
- 关闭开关清除待通知计划。iOS 由系统投递预先安排的本地通知；Android 使用无需精确闹钟权限的非精确 AlarmManager，并在重启与 App 恢复时恢复持久计划。

## 实际限制

这是预计结束提醒与前台核对完成状态的组合，不是服务端推送。付款后如果没有返回 App 查询到运行状态，就无法安排预测。系统通知权限、专注模式、安卓省电及强制停止可能阻止或延后投递。未承诺 App 被杀后实时查询到确切完成事件。

单纯预测到时的文案始终是“预计洗衣结束”，不会自动改变服务器订单状态。未增加下单、付款、取消或启动接口，没有实现未经验证的“立刻洗衣”。

## 验证

- 新增 Swift 提醒策略测试 3 项，通过；覆盖完成与失败区分、历史与重复提醒抑制、未启动订单、过期/未来时间及无效剩余时间。
- Android 同类新增测试 3 项通过，最终完整单元测试共 76 项、0 失败。
- iOS 模拟器构建通过；不代表真机锁屏通知验收。
- Android 最终 assembleDebug、testDebugUnitTest、lintDebug 全部通过；Lint 0 错误，仍有代码风格/本地化等警告。使用独立临时构建目录并关闭本轮 Kotlin 增量编译，避免原目录重复 BuildConfig 与增量缓存影响。
- 手机只打开原有 App 和订单核对页，随后按用户选择关闭核对页。没有创建订单或进行付款，候选功能尚未装入手机。

构建日志保存在本机 /tmp/campus-laundry-reminders-ios.log、/tmp/campus-laundry-reminders-tests.log 和 /tmp/campus-laundry-reminders-android-final.log。原构建目录的两份重复生成文件移至 /tmp/campus-reminder-generated-duplicates 保留，未清除用户配置或源码。

# 立刻洗衣：短时后台核对候选 build54

状态：本地研究候选，基于 0.9.0 build53。手机仍为 build53，本次不连接或覆盖手机，不发布 Release；Android 未加入此候选。

## 用户流程

本人确认衣物、门盖、程序和金额，选择“立刻洗衣”并进入支付宝前，申请一次 iOS 有限后台执行时间。独立于前台页面生命周期的任务核对这笔订单；U净确认已支付、设备与程序匹配、处于可启动状态后，复用原控制器发送一次启动。正常洗衣不会申请这段后台时间。

监测窗口从拉起支付宝之前开始，软件上限为 45 秒；系统可提前结束，也可能不授予后台时间。每次查询结束后约一秒继续核对，实际频率受网络响应影响，不承诺固定几秒启动。完成、订单不再符合条件、支付入口打开失败、取消或执行时间到期时结束窗口，不循环续期。

后台窗口运行时，前台查单入口让位于同一个窗口；窗口停止后恢复原有前台核对。系统到期会取消正在进行的查询，付款状态更新也不能越过原有取消检查。启动尝试仍先持久化；结果未知时不重发控制。原有十分钟本单意图期限不变，不能通过重启或后台窗口延长期限。

这不是后台定时任务、后台推送或常驻服务，没有新增音频、定位、后台刷新等保活能力，也不需要把 U净登录交给远端服务器。

## 离线验证

139 项 XCTest + 68 项 Swift Testing，共 207 项通过。新增六项覆盖：

- 不符合条件的订单不申请后台时间、不查单。
- 运行时间被拒绝或立即到期时不查单。
- 订单已运行后结束窗口，并且只释放一次。
- 系统到期取消正在等待的查询，不重新申请时间。
- 旧窗口的完成不结束新的窗口。
- 收到已付款数据时发生后台到期：取消后不发送启动；之后前台核对能接续并且只启动一次。

iPhoneOS Release 构建通过。上述测试使用模拟运行时间和离线订单，不是支付宝实付或机器实际启动验收。

## 下一次正常洗衣的验收

1. 由本人在现场放好衣物并关门，确认本单选择“立刻洗衣”。
2. 本人完成支付宝付款，先停留在支付宝，观察机器是否自行启动，记录付款完成和机器动作的大致时间。
3. 若机器未动，回校日常核对本单。确认是“未启动”“正在启动”还是结果不明，不重复创建订单或发送启动。
4. 后续正常使用再验证付款耗时超过后台时间时，回到 App 仍能接续。本次研究不额外制造真实交易测试。

本机 LaundryCache/payment-background-window.json 只保存 requested/granted/denied/systemExpired/localLimitReached/ended 和时间，不含订单、设备、支付链接或凭据。结合原有启动请求/订单回复时间，可区分系统提前暂停、客户端窗口结束、U净尚未更新付款和机器响应延迟。诊断仅留本人本机，不自动上传。

## 官方依据

https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time

Apple 只授予有限执行时间，可能返回 invalid，并要求到期时结束任务。因此“短时后台”只能减少返回 App 的需要，不能承诺付款多久都自动启动。
